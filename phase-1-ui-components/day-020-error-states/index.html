Day 020 / 100 Phase 1 · UI Components

Error & empty states

The screens nobody designs until something goes wrong. Six states that turn a dead end into a next step: a helpful 404, a server error that retries itself, offline mode, empty screens, “you need access” and a dashboard where one broken part doesn't break the rest.

  • 6states
  • Autoretry & backoff
  • Offlinequeue & sync
  • Nodead ends

01

Halden · Helpful 404 page

A “page not found” that actually helps. It guesses what you meant from the broken address, offers a search and popular pages, and lets you report the broken link in one click. A little illustration follows your mouse.

  • “Did you mean”
  • Search
  • Report link
  • Playful, not cute

02

Atlas · Server error with auto-retry

When the server fails, don't make people guess. It explains in plain words, retries by itself with growing waits (2 s, 4 s, 8 s…), shows a reference code support can look up, and links to the status page. It succeeds on the third try.

  • Exponential backoff
  • Countdown
  • Copy error ID
  • Status link

03

            
Lumen · Offline mode

            
Losing your connection shouldn't lose your work. While offline, the app keeps working, queues your changes and says so clearly. When you're back, it syncs everything and confirms. It reacts to your real connection too.

            
  • online / offline events
  • Queued changes
  • Sync on reconnect
  • Clear status
